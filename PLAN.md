- [x] Phase 20 — `internal/ingest/rtsp.go`'s `muxAnnexB` (called once per decoded H264/H265 access unit) grew its output via repeated `append` from a `nil` slice, causing 2-3 avoidable grow-and-copy reallocations per keyframe access unit (SPS+PPS+IDR in one AU). Fixed by summing the needed size upfront and allocating once (`make([]byte, 0, size)`) before the same append loop. The copy itself is required either way — `dec.Decode(pkt)` returns NALU slices that, for non-fragmented packets, view directly into the RTP packet's own payload buffer (`gortsplib`'s `rtph264`/`rtph265` decoders), which does not survive past the callback — this phase only removed the redundant re-growth, not the copy. G711/AAC's per-frame `append([]byte(nil), payload...)` was already a single correctly-sized allocation; left as-is. A live555-style "checkout a buffer, hand it to the network layer, return it to a pool when done" pattern was considered and rejected for the decoded-frame path specifically: unlike live555's single-use-then-discard network buffers, a decoded frame's backing slice is retained by `CapturePolicy`'s `FrameQueue` for the channel's whole retention window and, while recording, referenced (not copied) by the open segment's `Filler` too — both with variable, wall-clock-bounded lifetimes, not a bounded single-callback scope — so safe pooling would need per-frame reference counting across both owners for an uncertain payoff against Go's GC on frames this size/frequency.

## Context

`farc` (farcd) and `hls_server` (previous `PLAN.md`, now superseded by this one — see repo history) are two complete, working Go binaries with no web UI and no deployment artifacts. This plan adds a React SPA (`web/`) that doubles as an admin console (storage/channel management) and a VOD player, plus Dockerfiles and a docker-compose stack tying `farc`, `hls_server`, and the SPA together behind one nginx origin.

Scope decision (explicit): full admin console, not just a player — built with Vite + React + TypeScript + hls.js, no state-management or UI component library (three pages, one fetch layer, plain CSS).

## Real API surface the SPA is built against

**farcd (`internal/api`)** — admin/data plane:

```
POST   /storages                                  {id,path,geometry,params,force,catalog_path,backend} -> 201 {id,path,geometry}
GET    /storages                                  -> [{id,path,geometry}]
PATCH  /storages/{id}                              {retention_days?,write_mode?} -> 204
GET    /storages/{id}/candidates?channel=&t1=&t2=  -> [{index,uuid,begin,end}]
POST   /storages/{id}/fcontainers/{uuid}/protected {value:bool} -> 204
GET    /channels                                   -> [{channel,rtsp_url,storage,capture_policy_type,prerecord_ns,postrecord_ns}]
POST   /channels                                   {id,rtsp_url,storage,capture_policy:{type,max_deferred_start_ns,prerecord_ns,postrecord_ns}} -> 201
PUT    /channels/{id}                               {rtsp_url,storage,capture_policy:{...}} -> 200 (remove+re-add under the hood)
DELETE /channels/{id}                               -> 204
POST   /channels/{id}/capture-policy               {type,params:{prerecord_ns,postrecord_ns}} -> 204
POST   /channels/{id}/events                       {t?} -> 204
GET    /metrics                                    (Prometheus text; linked out, not parsed)
```

`resolve`, raw TOC/content routes (`GET .../toc`, `GET .../fcontainers/{uuid}`), and `/events/ws` are not used by the SPA — playback goes through `hls_server`, not through farcd's fallback-resolve path.

**hls_server (`internal/hlsapi`)** — 3 player-facing routes, all that exist:

```
GET /channels/{channel}/hls/{t1}/{t2}/playlist.m3u8
GET /segments/{channel}/{storage}/{uuid}/init.mp4
GET /segments/{channel}/{storage}/{uuid}/{n}/seg.m4s
```

    Follow-up 2: `hls_server.config.json` moved off a repo file bind-mount onto a Docker volume, mirroring `farc.config.json`'s own earlier migration. `internal/hlsconfig` gained `EnsureExists(path)` (writes `{"channels": []}` if nothing exists at path yet, no-op otherwise — hls_server has no `Save`, since it never rewrites this file itself, so `EnsureExists` builds and marshals a bare `&Config{Channels: []Channel{}}` inline rather than delegating to a shared save helper). `cmd/hls_server/commands/default.go` calls it before `Load`. `docker-compose.yaml`'s `hls_server` service swapped its `./deploy/hls_server.config.json:/etc/hls_server/hls_server.config.json:ro` bind mount for a new `hls_config:/etc/hls_server` named volume (not `:ro` — `EnsureExists` needs to write once on an empty volume); `deploy/hls_server.config.json` was deleted from the repo (nothing left to bind-mount). Verify: `internal/hlsconfig`'s new `TestEnsureExists_CreatesEmptyConfigWhenMissing`/`TestEnsureExists_LeavesExistingFileUntouched`; manual smoke test — a freshly built `hls_server` binary pointed at a nonexistent config path creates `{"channels": []}` and, given valid env, starts normally; `docker compose config` still validates.

12. **`hls_server` reconciles its channel set against farcd's live state (ADR-021).** `internal/api/eventpush.go` gained a "global" subscription mode (`subscribeMessage.Storage == ""`): `EventChannelCreated`/`EventChannelRemoved` consts, a `ChannelEvent{Name, Channel, Storage}` type, `pushMessage` gained `Channel`/`Storage` fields, `EventPushServer` gained a `globalSubs map[chan ChannelEvent]struct{}` fan-out plus `PublishChannelEvent`, `ServeHTTP` branches to a new `serveGlobal` before the existing per-storage `p.reg.Get` lookup, and a shared `watchDisconnect` helper factors out the disconnect-detection goroutine both paths use. `internal/farcd/farcd.go` gained an `f.push *api.EventPushServer` field (the same object already wired to `f.wsSrv`, now also reachable from the persist hooks) and `persistNewChannel`/`persistRemovedChannel` publish `EventChannelCreated`/`EventChannelRemoved` after a successful `config.Save`; `persistUpdatedChannel` publishes `removed`(old storage)+`created`(new storage) but only when the storage actually changed (a same-storage PUT publishes nothing). `internal/hlsclient` gained `ChannelInfo`+`ListChannels` (wraps `GET /channels`) and `Event`/`wirePushMessage` gained the same `Channel`/`Storage` fields — `Subscribe`'s signature didn't need to change, `Subscribe(ctx, "", []string{...}, nil)` already worked. `internal/tocindex/index.go` gained `Index.Remove(channel)` (deletes a channel's `ChannelIndex` entirely) — required, not optional: without it a channel moved to a different storage would keep serving stale records pinned to the old one forever, since only a full process restart used to throw the whole `Index` away. `internal/hlsapi/server.go`'s `channels map[uint16]bool` became a mutex-guarded `channelSet` (unexported, `Has`/`Add`/`Remove`) with exported `Server.AddChannel`/`RemoveChannel`; `handlers.go`'s three handlers (including `handlePlaylist`, the one that used to skip the check) call `s.channels.Has(channel)`. `internal/hlsd/hlsd.go` is the core rewrite: `Hlsd` gained `client`/`seed` fields, dropped its plain `[]*tocindex.EventSubscriber` for a `tracked map[uint16]*trackedSub{cancel, storage}` owned by exactly one goroutine (the new `reconcile`) for the process's whole lifetime — no mutex on `tracked`, by construction rather than by locking discipline (an earlier draft had a real concurrent-map-access bug from a separate eager seed-loop racing the reconcile goroutine; this design has only one writer, ever). `reconcile` seeds `tracked` from `cfg.Channels` (now just a bootstrap hint) then loops `reconcileOnce` (2s backoff on error, matching `tocindex.EventSubscriber`'s own convention); `reconcileOnce` does a full `applyRemoteList` diff (the reconnect catch-up, ADR-016-style) before subscribing to the global channel-lifecycle stream, then a `select` loop consuming both live events and a periodic (30s) re-list (bounds staleness from `PublishChannelEvent`'s drop-if-full policy); `startChannel`/`stopChannel` are idempotent, and `stopChannel` calls `h.index.Remove(id)` alongside cancelling the subscriber and updating the allow-set. Verify: `internal/api`'s new `TestEventPushServer_ServesGlobalSubscription`/`GlobalFiltersByWant`/`GlobalDropsWhenSubscriberBufferFull`/`ConcurrentPublishAndConnect` (`-race`); `internal/farcd`'s new `TestRun_CreateChannelOverHTTP_PublishesGlobalChannelCreatedEvent`/`RemoveChannelOverHTTP_...`/`UpdateChannelOverHTTP_StorageChanged_PublishesRemovedThenCreated`/`UpdateChannelOverHTTP_StorageUnchanged_PublishesNoGlobalEvent` (real `Farcd` + real WS dial) — its `newFarcdTestServer`-equivalent test fixtures across `internal/hlsd`/`internal/hlsclient` also gained real `IngestManager` wiring (`addChannel`/`removeChannel` helpers) so `GET /channels` reflects reality, fixing a fixture bug the new reconciliation logic exposed (a seed channel with no matching `IngestManager` entry got reconciled away immediately); `internal/hlsclient`'s new `TestClient_ListChannels`/`Subscribe_GlobalChannelEvents`; `internal/tocindex`'s new `TestIndex_Remove_ClearsChannel` and `TestEventSubscriber_Run_ReturnsNilOnContextCancel` (locks in that cancelling a subscriber's context never produces a spuriously-logged error); `internal/hlsapi`'s new `channelset_test.go` (`-race`) plus `TestServer_AddChannel_ThenRemoveChannel`; `internal/hlsd`'s new `TestRun_ChannelCreatedOnFarcd_ServedWithoutRestart`/`ChannelRemovedOnFarcd_StopsBeingServed`/`ChannelMovedToDifferentStorage_ReindexesFromNewStorage` (the last one distinguishes correct-vs-stale storage via the segment URI's embedded storage id, `/segments/{channel}/{storage}/...`, rather than decoding CMAF) and `TestHlsd_ConcurrentChannelChurnAndRequests` (`-race`); `tests/e2e_test.go`'s new `TestE2E_ChannelCreatedAndRemovedOnFarcd_ServedWithoutHlsServerRestart` (both real binaries start with zero channels, a channel is created/removed via real HTTP against the running `farc` process, `hls_server` picks it up/drops it live) — this also exposed and fixed the same fixture-authority bug in the *existing* `TestE2E_FarcAndHlsServerRealProcesses` (its `farc.config.json` had an empty `channels: []` while `hls_server.config.json` seeded channel 1 — now `farc.config.json` also declares it, since farcd's own config is what makes `GET /channels` report it).

## Gap resolutions

- **Gap 1 — no channel discovery — fixed in Phase 10.** `GET /channels` now lists every running channel (id, `rtsp_url`, storage, capture-policy type/params), backed by `IngestManager.List()`. `ChannelsPage` uses it directly instead of a raw channel-id input.
- **Gap 2 — no GET for capture-policy — effectively fixed as a side effect of Phase 10.** `GET /channels`' `capture_policy_type`/`prerecord_ns`/`postrecord_ns` fields are read live off each channel's `CapturePolicy` (`IngestManager.List()` → `CapturePolicy.Policy()`), not a stale copy — so the UI can now show the *current* policy, closing this gap without a dedicated route for it.
- **Gap 3 — `POST /storages` didn't persist into farcd's config — fixed in Phase 9.** `internal/farcd`'s `persistNewStorage` now appends the new entry to the in-memory `*config.Config` and calls `config.Save` before the HTTP response is written; a save failure rolls back the in-memory append and fails the request with 500 (the storage stays registered and usable for this process's lifetime regardless — persistence failing doesn't undo an already-completed `storage.Init`). Re-POSTing the same storage is still not a safe way to "repair" a missed persist: `storage.Init` with `force:false` returns `ErrAlreadyInitialized`, and `force:true` destroys the existing catalog.
- **Gap 4 — nanosecond timestamps exceed JS safe-integer range.** Handled client-side per the `ns.ts` design above; not a backend defect.
- **Gap 5 — `hls_server`'s channel list required a restart to pick up farcd changes — fixed in Phase 12.** `12-hls-server.md` §8's "источник истины для связки канал → хранилище" is resolved by ADR-021: farcd's live `GET /channels` plus a global `channel.created`/`channel.removed` WS subscription (`/events/ws`, `storage=""`) are now the source of truth, reconciled at startup, on every reconnect, and periodically while connected; the config file's `channels` list is only a bootstrap seed.
