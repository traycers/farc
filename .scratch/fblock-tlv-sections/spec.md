# Спека: TLV-конверт для верхнеуровневых секций фблока

Статус: open (проектирование, не принято)

См. `docs/docs/archive/adr/023-fblock-section-tlv-envelope.md` — полный контекст, сравнение с v1.0, обоснование и открытые вопросы. Этот файл — рабочий трекер задач, не дублирует ADR целиком.

## Что меняется

`03-storage-format.md` §12 (v2.0, предложение, не реализовано) — шесть верхнеуровневых секций фблока (Пролог/Каталог/Контрольные суммы/Контент/TOC/Эпилог) становятся однородными TLV-узлами:

```
magic_start | type | id | parent | sibling
| value_size | value | паддинг(?) до alignment
| crc32(заголовок до value) | crc32(value) | magic_finish
```

Отличия от списка полей, изначально предложенного пользователем (см. ADR-023 «Решение»):

- Убрано отдельное поле «size до конца секции» — вычисляется из `value_size` + `pad()` + фиксированный размер трейлера, чтобы не заводить второй источник истины.
- `magic_start` первого узла (Пролога) обязан остаться на смещении 0 фблока — иначе ломается детект `uninitialized` (ADR-006).

## Область действия

Только `03-storage-format.md` (верхний уровень фблока). `05-data-format.md`/`06-toc-format.md`/`07-media-tree.md`/`08-array-trees.md` (дерево фконтейнера, TOC) не меняются — их узлы остаются компактными AoS/SoA-элементами без magic/CRC/паддинга на узел (см. ADR-023 «Открытые вопросы» №2 — область действия подтверждена как рабочая гипотеза, требует явного да/нет от заказчика).
