# Спека: TLV-конверт для верхнеуровневых секций фблока

Статус: accepted (проектирование завершено 2026-08-24, ADR-023 «Принято»; реализация не начата)

См. `docs/docs/archive/adr/023-fblock-section-tlv-envelope.md` и `docs/docs/archive/03-storage-format.md` §12 — полная структура. Этот файл — рабочий трекер задач, не дублирует ADR/спеку целиком.

## Итоговая структура (v2.0)

- Фиксированная часть пролога (не узел дерева, смещение 0) — как в v1.0, но без `params_size`/`catalog_size` (не нужны для раскладки — её даёт эпилог).
- Дерево из 5 узлов: `root`(id0, физически материализован) → `params`/`catalog`/`content`/`toc` (id1-4, `parent=0`, цепочка `sibling`). Формат узла: `magic_start|type|id|parent|sibling|value_size|value|паддинг|crc32_header|crc32_value|magic_finish`. `value_size` — реальный размер (без дозаписи нулями до вычисленной ёмкости, как в v1.0).
- Эпилог (не узел дерева) — фиксированного размера/смещения от конца фблока, справочник `[type,id,offset,size,crc32]×5` + `count` (0..5) + `crc32_epilogue`. Перезаписывается атомарно (O(1)) после каждого завершённого узла — прогрессивный crash-recovery сигнал.
- Область действия: только верхний уровень фблока. `05`–`08`-data-format/media-tree/array-trees (дерево фконтейнера, TOC) не меняются.
- CRC32 везде, без CRC64. Мажорная версия v2.0.

## Как это разрешило исходные вопросы

- Сигнал завершённости записи (был блокирующим) — эпилог остаётся на фиксированном смещении (как v1.0), просто с более информативным телом; прогрессивная перезапись даёт даже больше, чем v1.0 (частичный, не только бинарный, сигнал).
- Дублирование поля `size` — снято, только `value_size`.
- Паддинг — да, на уровне узла (маленький, до `alignment`), не через дозапись Content нулями до полной ёмкости, как в v1.0 — это и дешевле по IO/CPU.
- CRC32 vs CRC64 — CRC32 везде.
