## О чём диссертация

Автор строит полный компилятор языка **Co-dfns** (лексически скопированный, динамически типизированный APL-диалект в синтаксисе dfns) и реализует **все проходы компилятора без ветвлений, без рекурсии и без ADT/record-абстракций** — только композиция стандартных array-примитивов APL над деревом, представленным как Structure-of-Arrays (SoA). Итоговый компилятор умещается в **17 строк APL-кода** против ~1000 строк эталонной реализации на фреймворке Nanopass (Racket/Chez Scheme), при этом на CPU обгоняет её в среднем в **~33 раза**, а на GPU — в **~200 раз**, используя на порядок меньше памяти под AST.

Главный тезис: непригодность деревьев для параллельных архитектур (SIMD CPU, GPU) — не свойство самих трансформаций дерева, а следствие традиционного выбора абстракций данных (указатель-ориентированные record-типы). Замена этой абстракции на плоские векторы (parent vector + производные колонки) и работа с деревом как с обычным array-данными снимает проблему почти без потерь в простоте кода.

## Терминология (сквозная по всем файлам)

- **dfns** — синтаксис анонимных функций APL (John Scholes), используемый как единственная форма определения функций во входном языке Co-dfns.
- **Guard** (`тест : следствие`) — единственная условная конструкция dfns; **Error Guard** (`::`) — перехват ошибок по кодам.
- **Parent vector** `p` — `p[i]` = id родителя узла `i`; корень указывает сам на себя (`p[i]=i`).
- **Referent** `r` — id ближайшего охватывающего узла-функции (лексический контур) для каждого узла.
- **Traversal idiom** — идиома «шаг вверх по `p` до предиката, до неподвижной точки» (`⍣≡`), основной инструмент bottom-up обхода в компиляторе.
- **SoA (Structure of Arrays)** — представление AST как набора параллельных векторов-колонок (`p`, `t` — type, `k` — kind, `n` — name/node-data, `r`), а не как записей-объектов с указателями.
