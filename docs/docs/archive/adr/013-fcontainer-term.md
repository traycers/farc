# ADR-013: Разделение терминов fblock и fcontainer

**Дата:** 2026-07-21
**Статус:** Принято

## Контекст

Термин «фблок» перегружен: он обозначает одновременно физический слот хранилища (пролог, каталог, контрольные суммы, эпилог — зона ответственности farc) и логическую единицу данных, которую заполняет потребитель («самодостаточна, может передаваться по сети, парситься независимо»).

Из-за этого в документах возникают натяжки:

- ADR-003 «отдаём фблок целиком по HTTP» — клиенту не нужен снимок каталога всего хранилища, лежащий внутри физического фблока; передавать имеет смысл данные потребителя.
- Требования называют фблок самодостаточной единицей передачи, хотя переносима и самодостаточна именно потребительская часть.
- Граница ответственности между библиотекой (физика хранения) и потребителем (структура данных) в терминологии не видна.

## Сравнение

### 1. Оставить один термин
- ✔ Документы и код менять не надо.
- ❌ Двусмысленность воспроизводится в каждом новом документе и наследуется API и кодом.
- ❌ Невозможно точно сформулировать, что именно экспортируется, передаётся по сети и чем владеет потребитель.

### 2. Ввести отдельный термин fcontainer
- ✔ Чёткая граница «физика хранилища / данные потребителя».
- ✔ Идентификация становится строже: индекс идентифицирует fblock, UUID — fcontainer.
- ✔ Название ложится в существующее семейство терминов (fblock, fchunk).
- ❌ Требуется вычитка и обновление всех существующих документов.

## Решение

Вводится термин **fcontainer (фконтейнер)**.

### Определения

- **fblock (фблок)** — физический слот хранилища фиксированного размера: пролог, каталог, контрольные суммы заголовка, область данных, эпилог. Внутренняя единица farc; адресуется индексом (`index * block_size`).
- **fcontainer (фконтейнер)** — структура и данные, которые заполняет потребитель: секции «Данные» и TOC. Размещается в области данных fblock. Внутреннее устройство непрозрачно для farc.

Один fblock содержит не более одного fcontainer.

### Принадлежность атрибутов

| Атрибут | Принадлежит | Комментарий |
|---------|-------------|-------------|
| Индекс | fblock | Физический адрес слота |
| UUID | fcontainer | Логический идентификатор данных, генерируется до записи |
| `begin` / `end` (актуальность) | fcontainer | Свойства данных потребителя |
| Срок хранения (retention) | fcontainer | Отсчитывается от `end` фконтейнера |
| `uninitialized` / `in_progress` / `ready` / `bad` | fblock | Состояния физического слота |
| `protected` | fblock | Флаг слота; защищает от перезаписи лежащий в нём fcontainer |

### Максимальный размер fcontainer

Накладные расходы fblock (пролог, каталог, контрольные суммы, эпилог) растут с количеством фблоков хранилища, поэтому максимальный размер fcontainer зависит от размера Storage.

- Вводится параметр инициализации — **минимальная доля fblock, гарантированная под fcontainer** (`min_container_share`, по умолчанию 70%).
- При инициализации вычисляется фактическая ёмкость: `fblock_size` минус накладные расходы. Если ёмкость меньше `min_container_share * fblock_size` — **создание хранилища завершается ошибкой**. Подбор `fblock_size` и количества фблоков — ответственность потребителя.
- Та же проверка выполняется при расширении хранилища: рост числа фблоков увеличивает каталог и уменьшает ёмкость новых записей. Если после расширения доля падает ниже порога — операция расширения отклоняется.

### API

- После открытия хранилища потребитель получает **максимальный размер fcontainer** и обязан учитывать его при заполнении данных. Буферы `FreeFblocksPool` имеют ровно этот размер.
- Значение может измениться после подтверждённого расширения/сужения хранилища — потребитель получает актуальное значение в ответе на операцию.
- Экспорт и передача по сети: передаётся fcontainer с минимальным конвертом метаданных (UUID, `begin`, `end`) — без конверта теряется идентификация.
- Уведомления (о начале записи, завершении, удалении) ссылаются на UUID fcontainer'а.

### Обновление документов

Существующие документы (`00-requirements.md`, `01-architecture.md`, `01-storage.md`, `02-storage-format.md`, `03-storage-operations.md`) подлежат вычитке: употребления «фблок» в значении «данные потребителя» заменяются на «фконтейнер». Физический смысл термина «фблок» сохраняется без изменений.

## Обоснование

Разделение терминов фиксирует границу ответственности, которая и так существует в формате (TOC и данные непрозрачны для Storage), но не была видна в терминологии. UUID, времена актуальности и retention естественно относятся к данным потребителя, а состояния слота и его физический адрес — к хранилищу. Явный порог доли fcontainer в fblock превращает молчаливую деградацию полезной ёмкости (каталог съедает место при больших хранилищах) в раннюю ошибку конфигурации на этапе создания хранилища.
