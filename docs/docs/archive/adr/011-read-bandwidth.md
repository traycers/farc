# ADR-011: Гарантированный прогресс чтения при непрерывной записи

**Дата:** 2026-07-21
**Статус:** Предложено

## Контекст

ADR-005 даёт записи абсолютный приоритет: чтение выполняется в паузах между записями, между порциями чтения проверяется очередь записи (`00-requirements.md` §4.4). Видеоархив пишет непрерывно: при нагрузке записи, близкой к пропускной способности диска, пауз может не быть вовсе — очередь чтения голодает неограниченно долго, просмотр архива на нагруженной системе фактически недоступен. Требования гарантируют, что данные не теряются, но не гарантируют прогресса чтения.

## Сравнение

### 1. Оставить абсолютный приоритет как есть
- ✔ Ничего не меняется, максимальная защита записи.
- ❌ Чтение может не выполняться никогда — деградация основной пользовательской функции (просмотр архива).
- ❌ Голодание невидимо для потребителя до жалоб пользователей.

### 2. Детерминированная квота чтения
После каждых `M` записанных фчанков выполнять до `K` порций чтения (при непустой очереди чтения), даже если очередь записи не пуста. При переходе `WriteQueue` в состояние BACKPRESSURE квота отключается — приоритет записи снова абсолютный.

- ✔ Гарантированный прогресс чтения в нормальном режиме.
- ✔ Главный инвариант сохранён: при перегрузке данные записи не задерживаются.
- ✔ Минимальное изменение цикла `StorageEngine`: вместо безусловной проверки очереди записи — счётчик квоты.
- ❌ Два новых параметра конфигурации (`M`, `K`).

### 3. Дедлайны запросов чтения
Каждому запросу чтения назначается дедлайн; по истечении запрос вклинивается перед записью.

- ✔ Ограничивает худшую задержку чтения.
- ❌ Сложная реализация: планировщик с приоритетами вместо FIFO.
- ❌ Пик просроченных дедлайнов способен задержать запись в самый неподходящий момент.

## Решение

Детерминированная квота чтения (вариант 2), уточняющая ADR-005:

- Нормальный режим (`WriteQueue` в NORMAL или WARNING): после каждых `M` записанных фчанков `StorageEngine` выполняет до `K` порций чтения из очереди чтения. Значения по умолчанию подбираются при реализации из расчёта задержки записи не более сотен миллисекунд (например, `M = 16` фчанков, `K = 4` порции).
- Режим перегрузки (`WriteQueue` в BACKPRESSURE): квота отключена, приоритет записи абсолютный — поведение ADR-005 без изменений.
- Метрики: время ожидания запроса в очереди чтения (максимум и перцентили за окно) доступны потребителю через API.

## Обоснование

Абсолютный приоритет записи был принят, чтобы не терять поток данных; квота сохраняет эту гарантию (при перегрузке она исчезает), но исключает бесконечное голодание чтения в устойчивом режиме. Детерминированная схема «M фчанков — K порций» предсказуема, дёшева в реализации и легко наблюдаема в метриках, в отличие от планировщика с дедлайнами.
