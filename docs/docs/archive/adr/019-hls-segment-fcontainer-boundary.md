# ADR-019: HLS-сегмент не пересекает границу fcontainer

**Дата:** 2026-08-04
**Статус:** Принято

## Контекст

`hlsd` (`12-hls-server.md`) режет данные канала за запрошенное окно `[t1, t2]` на HLS-сегменты. Окно произвольно и может охватывать несколько fcontainer подряд (обычный случай при воспроизведении интервала, превышающего срок жизни одного fcontainer). Нужно решить, задаётся ли сетка границ сегментов один раз на весь канал (сквозная, независимая от границ fcontainer), или отдельно для каждого fcontainer.

## Сравнение

### 1. Единая сетка по каналу, сегмент может пересекать несколько fcontainer
- ✔ Более равномерная длительность сегментов — не укорачивается на границах fcontainer.
- ❌ Сборка одного сегмента требует чтения из двух независимых fcontainer (потенциально даже из разных хранилищ после импорта, `00-requirements.md` §9) и согласования данных между ними в одном мукс-вызове.
- ❌ Перезапись одного из двух fcontainer при циклической записи (`fblock.deleted`) может испортить уже закэшированный сегмент, зависящий от данных обоих — инвалидация кэша перестаёт быть локальной операцией над одним ключом.
- ❌ Ключ кэша сегмента усложняется: вместо `(storage id, uuid, номер)` — потенциально диапазон, затрагивающий два `uuid`.

### 2. Сетка сегментов начинается заново на границе каждого fcontainer
- ✔ Один сегмент собирается из данных ровно одного fcontainer — простой ключ кэша `(storage id, fcontainer UUID, номер сегмента внутри контейнера)` (`12-hls-server.md` §4.5).
- ✔ Соответствует инварианту самодостаточности fcontainer (ADR-013, `00-requirements.md` §3.1): fcontainer уже спроектирован как единица, читаемая независимо от других, — сегментация не создаёт межконтейнерных зависимостей там, где остальная архитектура их сознательно избегает.
- ✔ Перезапись/удаление одного fcontainer (`fblock.deleted`) не может испортить уже отданный или закэшированный сегмент, целиком лежащий в другом fcontainer.
- ❌ Последний сегмент перед границей fcontainer может оказаться короче номинальной целевой длительности.
- ❌ На стыке двух fcontainer в одном плейлисте может понадобиться `#EXT-X-DISCONTINUITY`, если активный `config` (SPS/PPS/ASC) у них отличается (`12-hls-server.md` §4.3).

## Решение

Сетка сегментов строится отдельно для каждого fcontainer и не пересекает его границы. Каждый сегмент содержит данные ровно одного fcontainer.

## Обоснование

fcontainer в самой архитектуре farc — намеренно самодостаточная единица (ADR-013): её нельзя корректно интерпретировать, ссылаясь на данные другого fcontainer. Сегментация, пересекающая эту границу, вводила бы межконтейнерную зависимость искусственно, только ради равномерной длительности сегментов — а её цена (усложнённый кэш-ключ, риск испортить сегмент чужой перезаписью) выше пользы. Укорачивание последнего сегмента перед границей — не системная проблема: fcontainer живёт значительно дольше одного HLS-сегмента (секунды против типичного времени жизни fcontainer), так что короткий сегмент — редкое пограничное событие, а не типичный случай.

## Открытые вопросы

- Нужен ли отдельный запасной путь, если fcontainer настолько мал, что не вмещает ни одного полного сегмента номинальной длительности (короткий буфер, ADR-017) — не рассматривалось, предполагается редким случаем.
