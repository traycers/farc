# Заполнение фконтейнера

## 1. Назначение документа

Документ описывает **API**, которым потребитель добавляет данные в дерево ещё заполняемого фконтейнера — то есть что можно вызвать и что это значит в терминах дерева (`07-media-tree.md`). Как заполнитель физически размещает это в дереве (выделение `id`, смещений под `value`, продолжение `sibling` при параллельных вызовах) — целиком внутренняя реализация заполнителя, не специфицируется ни здесь, ни где-либо в документации формата.

Документ **не описывает**:
- Сам бинарный формат дерева/фконтейнера — `05-data-format.md`.
- Доменные роли и иерархию дерева — `07-media-tree.md`.
- Работу с фконтейнером целиком как буфером WritePool/WriteQueue Storage — `01-architecture.md` §2.1, `00-requirements.md` §4.7–4.8.

## 2. Заполнитель

**Заполнитель** — компонент, отвечающий за дерево одного заполняемого фконтейнера. Он предоставляет потребителю ровно два действия (ниже). В какую конкретно часть дерева это ляжет и как разные вызовы безопасно совмещаются друг с другом — решает сам заполнитель; это не часть контракта с потребителем.

## 3. Добавить параметры потока

Потребитель передаёт: канал, поток, вид (`video`/`audio`), параметры кодека (байты) и момент смены.

Заполнитель гарантирует: к этому моменту в дереве существуют канал, поток и ветка нужного вида (создаёт при первом обращении, `07-media-tree.md` §2), и что после вызова в дереве появляется новая `params_version` с указанным моментом смены и вложенным `data` (`07-media-tree.md` §3, §5).

## 4. Добавить кадры потока

Потребитель передаёт: канал, поток, один или несколько кадров (байты, время, и `I`/`P` для видео или код кодека для аудио).

Заполнитель гарантирует: каждый кадр появляется в дереве как новый `frame` с детьми `frame_data`/`frame_time` и `frame_kind_video` или `frame_codec_audio` (`07-media-tree.md` §3, §5), под самой последней `params_version` этого канала/потока, в переданном порядке.

## 5. Что вне контракта

Всё, что нужно, чтобы сделать это безопасно при параллельных вызовах разных потоков-производителей (выделение `id` и смещений, продолжение цепочки `sibling`, конкретный алгоритм размещения) — целиком внутренняя реализация заполнителя. Контракт с потребителем — только эти два действия и их результат в терминах дерева, не более.
