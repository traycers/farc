# Бинарный формат фблока

## 1. Назначение документа

Документ описывает бинарный формат Storage: разбиение хранилища на фблоки и бинарный формат самого фблока — расположение и размеры полей, порядок байтов, контрольные суммы, правила парсинга. Является спецификацией для реализации чтения и записи фблоков.

Документ **не описывает**:
- Концептуальную модель данных, компоненты и их ответственность — см. `02-storage.md`.
- Алгоритмы операций (сканирование при старте, выбор фблока для записи, расширение, сужение) — см. `04-storage-operations.md`.

## 2. Общие соглашения

- Порядок байтов: **Little Endian** (LE) для всех многобайтовых целых.
- Временные метки: **Unix timestamp в наносекундах**, uint64.
- Контрольные суммы: **CRC32** (IEEE 802.3, полином `0x04C11DB7`).
- Строки: UTF-8, без BOM.

## 3. Общая структура

### 3.1. Хранилище — массив фблоков

Storage — файл или блочное устройство, целиком занятое **массивом фблоков одинакового размера**. Ничего кроме фблоков в Storage нет: ни глобального заголовка, ни суперблока, ни таблицы размещения, ни списка свободных мест. Заголовки распределены по самим фблокам (ADR-001, ADR-002).

```
 смещение:  0            B            2B           3B          (N-1)·B      N·B
            ┌────────────┬────────────┬────────────┬─ ─ ─ ─ ─ ─┬────────────┬─────────┐
 Storage    │  Фблок 0   │  Фблок 1   │  Фблок 2   │    ...    │ Фблок N-1  │  хвост  │
            └────────────┴────────────┴────────────┴─ ─ ─ ─ ─ ─┴────────────┴─────────┘
 состояние:     ready        ready     in_progress              uninitialized  не исп.
            │←─ B байт ─→│

            B = fblock_size — одинаков для всех элементов массива
```

Свойства, вытекающие из этой раскладки:

- **Адресация — арифметика, а не поиск.** Начало фблока: `offset(index) = index × fblock_size`. Физический индекс `0..N-1` и есть адрес; таблицы трансляции «индекс → смещение» не существует.
- **Число элементов** `N = storage_size / fblock_size` — целочисленное деление (`04-storage-operations.md` §3.1). Остаток `storage_size mod fblock_size` меньше одного фблока и не используется.
- **Шаг массива известен из любого элемента.** `fblock_size` лежит в фиксированной части пролога каждого фблока (§5.1) и фиксируется при инициализации, поэтому прочитавший любой фблок читатель умеет адресовать все остальные.
- **Фблок 0 — не заголовок хранилища.** По формату он такой же элемент массива, как остальные. Выделен он лишь тем, что записывается при инициализации и потому гарантированно содержит валидный пролог с параметрами Storage (`04-storage-operations.md` §2.2, §3.1). Проверка «инициализирован ли Storage» — это чтение первых 8 байт, то есть `magic_prolog` нулевого элемента.
- **Элемент самодостаточен.** Каждый фблок содержит собственный заголовок (ADR-001), а его каталог — снимок состояния всех `N` элементов на момент записи (§6). Поэтому массив восстанавливается сканированием и читается начиная с любого элемента, без внешних структур.
- **Пустой элемент — не дыра, а состояние.** Незаписанный фблок физически занимает своё место, но не содержит валидного `magic_prolog` и потому опознаётся как `uninitialized` (ADR-006). Место под все `N` элементов размечено с момента инициализации.
- **Запись выбирает элемент по состоянию, а не по свободному месту.** Писатель обходит массив, беря сначала `uninitialized`, затем `ready` с истёкшим сроком хранения (`02-storage.md` §2.4). Аллокатора нет — есть перебор слотов.

Карта адресов:

| Индекс | Начало                | Конец (включительно)      |
| -----: | --------------------- | ------------------------- |
|      0 | `0`                   | `fblock_size - 1`         |
|      1 | `fblock_size`         | `2 × fblock_size - 1`     |
|    `k` | `k × fblock_size`     | `(k+1) × fblock_size - 1` |
|  `N-1` | `(N-1) × fblock_size` | `N × fblock_size - 1`     |

### 3.2. Секции фблока

Фблок — непрерывная область фиксированного размера на диске. Состоит из шести секций:

```
┌─────────────────────────────────────────┐
│ Пролог                                  │  Фиксированная часть + параметры (JSON)
├─────────────────────────────────────────┤
│ Каталог                                 │  Снимок состояния всех фблоков (SoA)
├─────────────────────────────────────────┤
│ Контрольные суммы заголовка             │  CRC32 × 3
├─────────────────────────────────────────┤
│ Контент                                 │  Payload
├─────────────────────────────────────────┤
│ TOC                                     │  Оглавление контента (непрозрачно для Storage)
├─────────────────────────────────────────┤
│ Эпилог                                  │  magic + CRC32 контента + CRC32 TOC + размер TOC
└─────────────────────────────────────────┘
```

Чтение фблока выполняется с двух сторон: пролог и каталог — с начала, эпилог — с конца.

## 4. Версионирование формата

Формат имеет мажорную и минорную версии, записанные в фиксированной части пролога:

- **Мажорная версия** (`format_version_major`, uint16) — изменяется при несовместимых изменениях. Библиотека отказывается работать с хранилищем несовместимой мажорной версии.
- **Минорная версия** (`format_version_minor`, uint16) — изменяется при обратно совместимых расширениях. Библиотека старшей минорной версии читает хранилища младших минорных версий той же мажорной версии.

Текущая версия формата: **v1.0**.

## 5. Пролог

Пролог — начальная секция фблока. Содержит фиксированную часть и параметры хранилища в формате JSON.

### 5.1. Фиксированная часть

Фиксированная часть пролога **никогда не меняет свою структуру**. Поля, их размеры и смещения постоянны для всех версий формата — это гарантия того, что любая библиотека может прочитать базовую идентификацию фблока.

| Смещение | Размер | Тип    | Поле                 | Описание                                                                                |
| -------- | ------ | ------ | -------------------- | --------------------------------------------------------------------------------------- |
| 0        | 8      | bytes  | magic_prolog         | `0x46 0x41 0x52 0x43 0x50 0x52 0x4F 0x4C` (`FARCPROL`). Идентифицирует начало фблока.   |
| 8        | 2      | uint16 | format_version_major | Мажорная версия формата.                                                                |
| 10       | 2      | uint16 | format_version_minor | Минорная версия формата.                                                                |
| 12       | 2      | uint16 | max_channels         | Ёмкость регистра каналов (`C`), фиксируется при инициализации (ADR-014).                |
| 14       | 2      | —      | reserved             | Зарезервировано, должно быть 0.                                                         |
| 16       | 8      | uint64 | write_sequence       | Монотонный счётчик записей (ADR-008). Определяет порядок фблоков.                       |
| 24       | 8      | uint64 | catalog_time         | Время создания снимка каталога в Unix timestamp наносекундах. Для аудита и диагностики. |
| 32       | 8      | uint64 | fblock_size          | Размер фблока в байтах.                                                                 |
| 40       | 4      | uint32 | params_size          | Размер секции параметров в байтах.                                                      |
| 44       | 4      | uint32 | catalog_entry_count  | Количество записей в каталоге (равно количеству фблоков в Storage).                     |
| 48       | 4      | uint32 | catalog_size         | Размер каталога в байтах.                                                               |
| 52       | 4      | —      | reserved             | Зарезервировано, должно быть 0.                                                         |

**Итого: 56 байт.**

Отсутствие валидного `magic_prolog` означает, что фблок находится в состоянии `uninitialized` (ADR-006) — заголовок никогда не записывался.

### 5.2. Параметры (JSON)

Параметры хранилища следуют сразу за фиксированной частью, размер определяется полем `params_size`. Сериализованы в JSON (UTF-8, без BOM) согласно ADR-009.

Правила эволюции:
- Новые параметры — новые ключи в JSON.
- Парсер игнорирует незнакомые ключи (forward compatibility).
- Обязательные параметры, отсутствующие в JSON, — ошибка формата.

Ожидаемые параметры:

| Ключ                  | Тип     | Описание                                                                                                                                  |
| --------------------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `fchunk_size`         | integer | Размер единицы физической записи с верификацией, в байтах (алгоритм — `04-storage-operations.md` §7.3–7.4).                                                                                                                   |
| `read_chunk_size`     | integer | Размер порции чтения в байтах (ADR-005). По умолчанию равен `fchunk_size`. Должен быть кратен размеру кластера диска.                     |
| `write_mode`          | string  | Режим записи: `"cyclic"` или `"fill_until_full"` (`11-service-composition.md` §3, §5.2.4; влияет на `select_next_index`, `04-storage-operations.md` §6.2). |
| `retention.days`      | integer | Минимальный срок хранения фблока в днях после `end` (последнего timestamp данных фконтейнера).                                            |
| `min_container_share` | number  | Минимальная доля `fblock_size`, гарантированная под фконтейнер (ADR-013). По умолчанию `0.7`. Проверяется при инициализации и расширении. |

Пример:

```json
{
  "fchunk_size": 4194304,
  "write_mode": "cyclic",
  "retention": {
    "days": 30
  },
  "min_container_share": 0.7
}
```

### 5.3. Смещение следующей секции

Сразу после параметров, по смещению `56 + params_size`, расположена метка `magic_catalog` (8 байт, `"FARCCTLG"`) — см. §6. Сам каталог начинается сразу за ней, по смещению `56 + params_size + 8`.

## 6. Каталог

Каталог — снимок состояния всех фблоков Storage на момент начала записи текущего фблока, плюс регистр каналов (ADR-014). Расположен сразу после пролога, за меткой `magic_catalog`. Состоит из двух частей: **регистр каналов** (фиксированного размера, не зависит от `N`) и **per-fblock массивы**, сериализованные как **структура массивов** (Structure of Arrays, SoA) длины `catalog_entry_count`.

Перед каталогом располагается метка `magic_catalog` — 8 байт, `0x46 0x41 0x52 0x43 0x43 0x54 0x4C 0x47` (`"FARCCTLG"`). Метка не входит в `catalog_size` и не покрывается `crc32_catalog` (§7) — это независимая от контрольной суммы, дешёвая проверка того, что вычисленное по `params_size` смещение действительно указывает на начало каталога, а не на повреждённые из-за плохого `params_size` байты. Несовпадение метки при совпадающей `crc32_params` — верный признак того, что повреждён именно `params_size`, а не JSON параметров.

### 6.1. Регистр каналов

Регистр — таблица соответствия «номер канала → компактная позиция в битовой маске», общая для всего Storage (не повторяется по фблокам):

| Смещение от начала каталога | Размер (байт) | Поле               | Элемент                                                                                 |
| --------------------------- | ------------- | ------------------ | --------------------------------------------------------------------------------------- |
| 0                           | C × 2         | channel_registry[] | uint16 — номер канала, занимающий позицию `0..C-1`; `0` = позиция никогда не выделялась |

где `C` = `max_channels` (см. §5.1). Итого: `C × 2` байт.

Номер канала `0` зарезервирован (ADR-014, реальные номера — `1..65535`), поэтому `channel_registry[i] == 0` однозначно означает «позиция `i` никогда не выделялась», а `channel_registry[i] != 0` — «когда-то выделялась» (текущим или уже переиспользованным номером). Поскольку новые позиции всегда выделяются по возрастанию наименьшего свободного индекса, когда-либо выделенные позиции образуют непрерывный префикс `[0, k)` без дыр — эта граница `k` не хранится отдельным полем, а вычисляется одним проходом по массиву при загрузке каталога (тот же проход, что уже нужен для подсчёта ссылок на позиции, ADR-014).

### 6.2. Per-fblock массивы

Расположены сразу после регистра, со смещением `C × 2` от начала каталога. Массивы идут последовательно, без заголовков между ними. Порядок и формат фиксированы мажорной версией формата.

Для версии v1.0:

| Смещение от начала per-fblock части | Размер (байт)   | Поле             | Элемент                                                                         |
| ----------------------------------- | --------------- | ---------------- | ------------------------------------------------------------------------------- |
| 0                                   | N × 1           | flags[]          | uint8 — состояние и флаги (см. 6.3)                                             |
| N × 1                               | N × 16          | uuid[]           | 16 байт — UUID фконтейнера                                                      |
| N × 17                              | N × 8           | begin[]          | uint64 — время начала актуальности (ns)                                         |
| N × 25                              | N × 8           | end[]            | uint64 — время окончания актуальности (ns)                                      |
| N × 33                              | N × ceil(C / 8) | channel_bitmap[] | бит на компактную позицию `0..C-1` — присутствие канала в фконтейнере (ADR-014) |

где `N` = `catalog_entry_count`.

**Итого на запись: `33 + ceil(C / 8)` байт.**

**Полный размер каталога:** `catalog_size = C × 2 + N × (33 + ceil(C / 8))`.

Пример: при `C = 256` (запас на 64 текущих канала) запись каталога — `33 + 32 = 65` байт; для 1 миллиона фблоков каталог занимает ≈ 65 МБ плюс несущественные `512` байт регистра.

Порядок массивов (flags первым) выбран сознательно: при сканировании можно прочитать только массив flags (1 байт на фблок) и быстро получить карту состояний без чтения UUID, временных меток и битовых масок.

### 6.3. Кодирование flags

Байт flags:

| Бит | Маска | Значение | Описание                       |
| --- | ----- | -------- | ------------------------------ |
| 0-1 | 0x03  | 0        | `uninitialized`                |
|     |       | 1        | `in_progress`                  |
|     |       | 2        | `ready`                        |
|     |       | 3        | `bad`                          |
| 2   | 0x04  | 1        | `protected`                    |
| 3-7 |       |          | зарезервированы, должны быть 0 |

Значение `uninitialized = 0` соответствует нулевому байту — естественное состояние свежевыделенной или нулевой области памяти/диска (ADR-006).

Для `uninitialized` фблоков значения в массивах `uuid[]`, `begin[]`, `end[]`, `channel_bitmap[]` (не заполнены, фконтейнера нет) должны быть нулевыми (не используются, но должны быть предсказуемыми для CRC-проверки).

### 6.4. Свойство снимка

Снимок каталога в заголовке фблока `K` отражает состояние Storage на момент начала записи `K`:
- Сам `K` в собственном снимке помечен `in_progress`.
- Предыдущий успешно записанный фблок помечен `ready`.

Подтверждение «фблок `M` успешно записан» попадает на диск в каталоге следующего записанного фблока `M+1`. Изменения регистра каналов (новая регистрация, переиспользование позиции) подчиняются тому же правилу отложенного подтверждения (ADR-014) — это часть того же снимка индексов, что и переходы состояний фблока.

## 7. Контрольные суммы заголовка

Три контрольных суммы расположены последовательно сразу после каталога. Позволяют определить, какая именно часть заголовка повреждена.

| Смещение от начала секции | Размер | Тип    | Поле          | Покрывает                                  |
| ------------------------- | ------ | ------ | ------------- | ------------------------------------------ |
| 0                         | 4      | uint32 | crc32_fixed   | Фиксированная часть пролога (байты 0..55). |
| 4                         | 4      | uint32 | crc32_params  | JSON параметров целиком.                   |
| 8                         | 4      | uint32 | crc32_catalog | Каталог целиком.                           |

**Итого: 12 байт.**

Смещение секции от начала фблока: `56 + params_size + 8 + catalog_size` (с учётом метки `magic_catalog`, §6).

### 7.1. Диагностика повреждений

| crc32_fixed | crc32_params | crc32_catalog | Интерпретация                                                                                                                                           |
| ----------- | ------------ | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ✓           | ✓            | ✓             | Заголовок целый.                                                                                                                                        |
| ✓           | ✓            | ✗             | Параметры доступны, снимок каталога потерян.                                                                                                            |
| ✓           | ✗            | ✓             | Каталог доступен, параметры повреждены.                                                                                                                 |
| ✓           | ✗            | ✗             | Только фиксированная часть валидна.                                                                                                                     |
| ✗           | —            | —             | Фблок нечитаем — либо повреждён, либо `uninitialized`. Для различения смотрят на `magic_prolog`: совпадает → повреждён, не совпадает → `uninitialized`. |

Проверка `magic_catalog` (§6) — более дешёвый первый шаг перед вычислением `crc32_catalog`: несовпадение метки означает, что офсет каталога уже вычислен неверно (скорее всего, повреждён `params_size`), и читать/хешировать сам каталог для диагностики не нужно — ошибка обнаружена раньше и дешевле.

## 8. Контент и TOC — фконтейнер

Секции «Контент» и «TOC» вместе составляют **фконтейнер** (ADR-013) — структуру и данные, заполняемые потребителем. Для Storage обе секции непрозрачны: интерпретация выполняется потребителем через Reader.

### 8.1. Контент

Перед контентом располагается метка `magic_content` — 8 байт, `0x46 0x41 0x52 0x43 0x43 0x4F 0x4E 0x54` (`"FARCCONT"`). Как и `magic_catalog` (§6), она не входит в размер контента и не покрывается `crc32_content` (§9) — независимая проверка того, что смещение, вычисленное из `params_size`/`catalog_size`, действительно указывает на начало контента.

Контент (payload) расположен сразу после метки `magic_content`. Физически записывается и верифицируется по алгоритму write-verify — `04-storage-operations.md` §7.3.

Смещение метки `magic_content` от начала фблока: `56 + params_size + 8 + catalog_size + 12`. Смещение самого контента: `56 + params_size + 8 + catalog_size + 12 + 8`.

### 8.2. TOC (Table of Contents)

Перед TOC располагается метка `magic_toc` — 8 байт, `0x46 0x41 0x52 0x43 0x54 0x4F 0x43 0x30` (`"FARCTOC0"`). Как и остальные внутренние метки, она не входит в `toc_size` и не покрывается `crc32_toc` (§9) — независимая проверка того, что смещение, вычисленное из `toc_size` (хранится в эпилоге), действительно указывает на начало TOC, а не куда-то в середину контента из-за повреждённого `toc_size`.

TOC — оглавление контента фконтейнера. Расположен после метки `magic_toc`, перед эпилогом. Для Storage — непрозрачный массив байтов. Парсинг и интерпретация TOC — ответственность Reader. Формат TOC будет описан в отдельном документе при проектировании слоя полезных данных фконтейнера.

Размер TOC определяется полем `toc_size` из эпилога.

Смещение TOC от конца фблока: `20 + toc_size`. Смещение метки `magic_toc` от конца фблока: `20 + toc_size + 8`.

### 8.3. Максимальный размер фконтейнера

Максимальный размер фконтейнера (контент + TOC) равен `fblock_size - 112 - params_size - catalog_size` (см. карту смещений, раздел 10; 112 = 88 фиксированных байт секций заголовка/эпилога + 24 байта трёх внутренних меток `magic_catalog`/`magic_content`/`magic_toc`) и уменьшается с ростом `catalog_size` — то есть с ростом количества фблоков хранилища (`N`) **и** с ростом ёмкости регистра каналов (`C`, ADR-014): `catalog_size = C×2 + N×(33 + ceil(C/8))`. Инициализация и расширение хранилища завершаются ошибкой, если итоговый размер фконтейнера опускается ниже `min_container_share * fblock_size` (по умолчанию 70%, ADR-013). Потребитель получает актуальное значение при открытии Storage и после подтверждённых операций расширения/сужения.

## 9. Эпилог

Эпилог — фиксированная секция в конце фблока. Читается с конца фблока (последние 20 байт).

| Смещение от конца | Размер | Тип    | Поле          | Описание                                                                                                                                      |
| ----------------- | ------ | ------ | ------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| -20               | 8      | bytes  | magic_epilog  | `0x46 0x41 0x52 0x43 0x45 0x50 0x49 0x4C` (`FARCEPIL`). Отличается от `magic_prolog` — позволяет распознать эпилог даже при случайном чтении. |
| -12               | 4      | uint32 | crc32_content | CRC32 контента (payload).                                                                                                                     |
| -8                | 4      | uint32 | crc32_toc     | CRC32 TOC.                                                                                                                                    |
| -4                | 4      | uint32 | toc_size      | Размер TOC в байтах.                                                                                                                          |

**Итого: 20 байт.**

### 9.1. Роль эпилога при восстановлении после сбоя

Эпилог записывается последним. Наличие валидного `magic_epilog` — признак того, что запись фблока дошла до финальной стадии. При сбое питания во время записи фблока эпилог позволяет определить степень завершённости записи:

| magic_epilog | crc32_content | crc32_toc | Интерпретация                                                              |
| ------------ | ------------- | --------- | -------------------------------------------------------------------------- |
| ✓            | ✓             | ✓         | Запись завершена полностью. Контент и TOC целы.                            |
| ✓            | ✓             | ✗         | Эпилог записан, но TOC повреждён (крайне редко — записывается до эпилога). |
| ✓            | ✗             | —         | Эпилог записан, контент повреждён (физический дефект).                     |
| ✗            | —             | —         | Запись не дошла до эпилога — фблок `in_progress` на момент сбоя.           |

## 10. Карта смещений

Сводная таблица смещений всех секций от начала фблока:

| Секция                       | Начало                                       | Размер                                    |
| ---------------------------- | -------------------------------------------- | ----------------------------------------- |
| Пролог (фиксированная часть) | 0                                            | 56                                        |
| Параметры (JSON)             | 56                                           | params_size                               |
| `magic_catalog`              | 56 + params_size                             | 8                                         |
| Каталог                      | 56 + params_size + 8                         | catalog_size = C×2 + N × (33 + ceil(C/8)) |
| Контрольные суммы заголовка  | 56 + params_size + 8 + catalog_size          | 12                                        |
| `magic_content`              | 56 + params_size + 8 + catalog_size + 12     | 8                                         |
| Контент                      | 56 + params_size + 8 + catalog_size + 12 + 8 | вычисляется                               |
| `magic_toc`                  | fblock_size - 20 - toc_size - 8              | 8                                         |
| TOC                          | fblock_size - 20 - toc_size                  | toc_size                                  |
| Эпилог                       | fblock_size - 20                             | 20                                        |

Метки `magic_catalog`/`magic_content`/`magic_toc` не входят в размер соседних секций (`catalog_size`, размер контента, `toc_size`) и не покрываются их `crc32_*` — это независимая, дешёвая (8 байт) проверка того, что вычисленное смещение действительно указывает на начало нужной секции, до того как читать и проверять контрольной суммой саму секцию целиком (§6, §7.1, §8.1, §8.2).

Контент внутри фблока начинается с произвольного, не обязательно кратного выравниванию, смещения — и это не проблема. Физическая запись (ADR-010, ADR-017) не оперирует отдельно «заголовком» и «контентом» как двумя независимыми `O_DIRECT`-операциями: `StorageEngine` пишет **буфер фблока целиком** как один непрерывный поток байт (пролог+параметры+каталог+контрольные суммы+контент+TOC+эпилог), кусками, кратными выравниванию, начиная от смещения 0 фблока — а оно уже выровнено, т.к. `fblock_size` кратен выравниванию (ADR-010) и `offset(index) = index × fblock_size`. Граница между очередным записываемым куском и следующим определяется только накопленным объёмом готовых байт от начала фблока, а не логическими границами секций внутри него — кусок вполне может закончиться, например, посередине каталога. Отдельно выравнивать именно начало секции Контента не нужно.

Размер контента: `fblock_size - 56 - params_size - 8 - catalog_size - 12 - 8 - toc_size - 8 - 20 = fblock_size - 112 - params_size - catalog_size - toc_size` (с учётом трёх меток по 8 байт).
